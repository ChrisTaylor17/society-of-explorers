# Native member transport and storage: local integration candidate

This is a fail-closed JavaScript adapter contract and an independent, unregistered Apple policy prototype. There is no native bridge, provider client, sign-in flow, or actual OS storage in the app. Capability declarations are self-reported and do not establish security. Neither the Quest nor Expo default bootstrap installs these ports.

A future bridge must enforce the configured origin, route, header and redirect policy independently before attaching a bearer. The adapter rejects other routes, ambient credentials and redirects; an abort during reservation prevents credential handoff. After handoff cancellation is best effort, and an already sent write may commit. The bridge must independently bound response size and prevent cross-origin redirects before forwarding credentials. Provider authentication traffic requires its own equivalent transport protections.

The storage adapter maps only the SDK session, PKCE and optional user keys to fixed native slots. Calls on the same bridge object and storage key share one FIFO queue. Retirement blocks queued and future reads, writes, and deletions. Use the account-handover barrier before retirement for local account cleanup. A timed-out operation already running can still commit; a timed-out deletion that has not started is skipped. The same queue prevents a later operation in that process using the same bridge object from overtaking that delete. There is no crash, restart, cross-instance, or cross-proxy ordering guarantee, and retirement does not itself revoke a token or delete persisted data.

The standalone Apple source proposes ephemeral URLSession configuration, a rejecting redirect delegate and a non-synchronizing, device-only Keychain backend. Its command-line tests use a fake backend; no Keychain call or real request was made. It is not registered with Expo, linked into an app, checked on iOS hardware, or reviewed for release. Android has no native implementation in this candidate. Native secure storage, lifecycle and cancellation behavior, redirect containment, access-control review, production identity, and persistence remain release gates.
