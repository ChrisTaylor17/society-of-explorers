The registered app now opens agreed reading from a selected Circle. Each explicit **Read meeting selection** or **Read current selection** rechecks current Circle detail and compares the exact book, edition and inclusive range before opening the reader. A changed delivered plan requires another deliberate selection. Current SQL separately makes reading programs immutable. A nonmember may read a publicly available selection; this grants no membership or discussion authority.

The reader shows one canonical source block at a time, preserves its text and line breaks, and confines Previous/Next to the agreed range. Tables, images, other nontext content and empty blocks are identified in place. They are not silently skipped. Source attribution, license notice, edition notes and the US public-domain/outside-US-unassessed statement accompany validated responses. This is a text reader, not complete source-layout parity. Reading progress is not saved.

The separate optional `pinned-passage-v1` native capability permits only anonymous GET requests to the existing passage endpoint with exact ordered book, edition and block coordinates. It carries no member bearer, provider credential, Circle identity or request body. The discovery channel cannot fetch passages and the passage channel cannot fetch discovery or member routes. Both use the existing native handle, cancellation and durable generation engine. Kotlin source validates the bounded wire form; JavaScript and the canonical server validate the actual pinned edition and block range. No new bridge method or server route was added.

The canonical server verifies materialized source HTML and index hashes before returning passage text. The portable controller validates exact response coordinates, source hash, status, URL and pinned metadata. An offline-generated metadata snapshot checks all eight editions against the existing canonical metadata hashes; runtime comparison needs no native cryptography. The response hash is not client-side cryptographic proof of the returned text. The reader relies on the canonical server and approved HTTPS origin.

Background, blur, unknown/offline connectivity, account retirement and closure clear displayed text and invalidate outstanding work. Reconnection alone performs no request. Owner notifications terminally retire the chosen selection, even if an opaque owner scope happens to be reused. A separate directory intent fence prevents an old, ignored-abort detail response from opening a reader after the directory has retired or its selection changed. A failed passage can be retried manually at that exact position. The request deadline includes JSON decoding. Back closes the reader and rechecks Circle detail.
