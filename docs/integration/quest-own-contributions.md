# Quest Browser own contributions

`/quest/contributions` is an account-level entry for posted Circle messages. It requires no Circle ID, listing, metadata lookup or current membership. The Quest landing page and configured Circle page link to it. The existing selected-account bridge still requires a matching, verified Supabase web account; wallet-only users retain the regular web contributions link. No provider client is constructed until the member explicitly connects, and neither connecting nor checking the provider session loads contribution history.

The member explicitly loads their posted messages. The shared controller requests the canonical own-contributions API, replaces each bounded page, and accepts only author-owned DTOs. Selecting a contribution clears the list and checks its current message state separately. Only fresh author permissions enable withdrawal, with a deliberate acknowledgement and the same retained-evidence disclosure used on the web. These controls do not change AI consent; the standalone page links to the regular posted-messages page for those settings.

The configured Circle page also includes this account-level panel. Opening it clears and pauses the Circle workspace; returning clears contribution details and makes no automatic Circle request. An uncertain withdrawal blocks internal list/back/return navigation. A current-state GET cannot confirm that request; only an exact, manually requested POST replay can recover its receipt. Disconnect, account change, inactivity, offline connectivity and unmount retire private bodies, confirmations and pending local action details. A sent request may still complete.

The new DOM island is optional only as a complete set for older configured pages. Missing or duplicate known controls are rejected before account observation. A standalone entry requires the complete island. Product rendering uses text nodes, the existing bounded DTOs and the real Quest CSS. Own-history authority comes from the verified account, and message selection comes only from the current server page. No backend or SQL change is introduced.

## Verification and limits

`platforms/tests/browser-quest-contributions-composed.mjs` passes **8/8 stories**, **49 actual canonical handler requests** and **64 unchanged source/SQL bindings**. The fixture executes the actual standalone/configured `QuestCircle`, selected-account bridge, generated shared controller, DOM view, member/contribution/message handlers and the existing strict Circle SQL in disposable PGlite. It seeds 27 author contributions across two Circles, leaves both and quarantines both, then verifies 25-plus-2 paging without a Circle read. It also covers another account's exclusion, fresh hidden-message author state, explicit withdrawal, committed lost reply and exact replay, a real stale-revision refusal, held list/state/action retirement, offline clearing and no automatic reconnect fetch, embedded navigation and unmount cleanup.

The unchanged prior Quest message-action fixture also passes **8/8 stories**, **56 handler requests** and **62 current bindings** after rebuilding against the changed composition. Its historical source/assertions were not weakened. Scoped product/new-test lint passes; `git diff --check` passes. The 320px screenshot was visually inspected, and visible controls meet the browser fixture's minimum height/overflow checks. This is browser layout/keyboard evidence, not physical-headset accessibility or native rendering acceptance.

Provider identities, tokens, SDK events, HTTP delivery and Next Link are explicit synthetic adapters. Chromium runs at an intercepted virtual HTTPS origin with cached runtimes and startup external-network denial. One disposable PostgreSQL backend does not establish production contention, deployed account/cookie behavior, real provider verification, device acceptance or native sign-in ownership. The new standalone route's built-Next verification is recorded separately by the release runner. SQL remains unapplied, the provider remains disabled, and production release remains on hold.

Evidence uses `platforms/evidence/quest-contributions-composed*`; the receipt includes prior attempt receipts, exact hashes, route/error observations and confirmed owned browser/database cleanup. The initial new-fixture failure was an early pagination wait observing a deliberately cleared cursor before the next reply; the wait was corrected without changing product behavior.
