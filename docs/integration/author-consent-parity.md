# Native and Quest author consent

This checkpoint extends web account checkpoint `09ec9dc2290ff4963080efeb0e80a1570a037efd`. It adds per-message author AI permission to the registered native App and Quest Browser contributions. First release remains **HOLD**. No production migration, provider activation or device acceptance occurred.

Authors explicitly connect/check their account, load their contributions, select a message and check its current permission. The disclosure names Anthropic and explains retention, personal details embedded in message text, and the limits of revocation. Human review needs no AI permission. Legacy messages remain excluded. Permission changes themselves do not invoke a provider or send message text or reporter notes.

Allowing or reaffirming requires a fresh checkbox for the current selected message. Keep-off and revocation remain available after a fresh author-owned check, including where an author has left the Circle or their message is hidden or withdrawn. The current server response independently controls whether permission can be enabled. An accepted choice must return the exact next consent revision and then match a separate read before the client confirms it. Unchanged keep-off/reaffirm decisions use the existing unapplied consent-intent ordering migration.

Unknown writes never retry automatically. A subsequent read cannot cancel an earlier held request or confirm its outcome; a new explicit decision advances the ordering barrier. Closing or leaving clears local state with a warning that sent work may finish. Consent and withdrawal operations serialize, including synchronous observer callbacks. Selection, account, lifecycle and interaction generations retire previous callbacks, even when the same message is reopened. This also protects the existing withdrawal and navigation controls.

The native bridge advertises `author-message-ai-consent-v1`. JavaScript and Kotlin independently limit the new endpoint to GET or an exact four-field POST containing revision, content hash, policy and boolean choice. The native capability propagates through the existing verified-account connection. Older bridges show an honest website fallback. Kotlin was inspected and checked statically; it was not compiled or run on a device.

Quest validates complete, nonduplicated consent markup before constructing its account client. It uses its existing owned account and request transport. All contribution DOM handlers capture the rendered interaction, including the original withdrawal controls. The public policy remains a normal browser link. This is the regular Quest Browser experience, not immersive headset acceptance.

The current canonical member handler and current consent/message/contribution SQL were exercised. It covers explicit actions, exact receipts/readback, late enable/revoke conflicts, lost replies, stale enabled controls, withdrawal, offline disposal and legacy bridges.
- Quest passed **10 browser scenarios / 100 synthetic handler requests**, including real member intent/receipt matching with synthetic cookies and provider inputs. Missing markup fails before client creation. Cross-account, selection, focus, offline and unmount retirement were exercised, including an old enabled withdrawal callback while the new selected message had its own enabled withdrawal.
- Both browser proofs invoked **zero AI providers** and closed their browsers and disposable databases. Root inspected both 320px screenshots; text and controls fit without horizontal overflow. The browser fixtures check 44px action buttons; this is not complete accessibility acceptance.

Authentication provider responses, message-route actor resolution, PostgREST delivery, React Native rendering/lifecycle and protected OS storage are explicit doubles. Message/contribution actor resolution remains a lower-level synthetic boundary in both. No real credentials, email, provider account, native transport, Keystore, Codegen, Hermes or physical device were verified.

Earlier diagnostic receipts remain local. No baseline stale-callback defect was reproduced; callback checks are regressions against source-grounded risks.
