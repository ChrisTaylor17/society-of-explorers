# iOS member account core

The Swift account core implements the protected storage and request boundary behind the existing `NativeSoeMember` contract. Installed configuration supplies the app identity, member origin, storage key and optional provider origin and publishable key. A process-local guard allows one live authority for each resulting namespace. The previous Apple policy remains the provenance for the device-only Keychain attributes. [Apple Keychain accessibility documentation](https://developer.apple.com/documentation/security/ksecattraccessiblewhenunlockedthisdeviceonly)

The vault stores one bounded record with a generation and three ordinary slots. Email recovery has a separate native-only binding. Reset first retires the native scopes and transfers, then checks storage and writes a secret-free marker. A read-back-confirmed empty successor completes the reset. Reopening a committed marker recovers that empty successor. A failure before the marker commits leaves the durable outcome uncertain, and an ambiguous operation closes its current vault. Separate processes need their own coordination.

Foreground, protected data and connectivity determine which calls may proceed. The bridge must capture the native stamp before queueing work. Offline foreground storage and a protected cold-launch email callback have separate admission rules. Network requests consume one lease with a monotonic deadline and exact storage generation. The policy separates ordinary member, message reviewer, Circle reviewer, provider authentication and public reads. The Foundation transport bounds the response, refuses redirects and authentication challenges outside system server trust, and uses an ephemeral configuration without cookies or credential storage. The device run must observe URLSession’s wire behavior as well as the application lease. [Apple ephemeral session documentation](https://developer.apple.com/documentation/foundation/urlsessionconfiguration/ephemeral)

Email signup, resend and recovery use the exact installed callback and S256 proof. Claiming a callback erases the stored binding before returning the code and verifier. The temporary recovery authority requires the correct purpose, exact subject and fresh provider proof before the password change. A lifecycle change, cancellation or deadline retires the claim and its requests. The ordinary password lane remains separate.

The Mac suite uses a synthetic atomic record backend and synthetic provider responses. It exercises the composed authority and also creates and cancels an actual Foundation task under an OS network-deny profile. A targeted regression reproduced a cancelled duplicate call stopping the authorized transfer. Per-call cancellation ownership now preserves the authorized transfer and drops replies to cancelled callers. Additional cases cover both pre-dispatch and in-flight expiry, reset before storage access, and stale close after namespace ownership has transferred. [Verification receipt](ios-member-core-verification.json)

The app still needs its React Native module registration, a generated iOS host, native delivery of the lifecycle and callback events, and iOS build and device checks. The inspected iOS SDK paths and application project were absent. The next integration must use the current `NativeSoeMember` Codegen surface and demonstrate actual Keychain access, installed links, provider sign-in, background transitions, and reply retirement before advertising iOS capabilities.
