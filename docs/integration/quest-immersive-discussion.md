# Quest immersive Circle discussion

Open a Circle in Quest Browser and connect the existing account. A compatible browser offers **Enter immersive room**. Entry pauses the regular Circle view and clears its private content. The room opens with a generic panel. One controller trigger checks the existing account, and a second checks current Circle membership and loads recent discussion.

The room shows up to five visible contribution previews from the first archive page. A controller trigger advances to the next preview and checks for current discussion after the last one. The panel displays the author label and a text excerpt. Canonical reply navigation stays in the regular archive, along with complete text, posting, moderation, source readings and the live meeting link. Use the headset controls or the regular page's Exit button to leave. The regular view requires a fresh member check on return. Shared immersive meetings remain a separate part of the Quest work.

The headset uses a distinct read-only lifetime and the same selected-account check as the regular Quest view. It confirms the SDK identity and cookie-selected account before the same-origin discussion GET for each load. The current archive handler and service-side membership rules decide access. The headset's visible state permits reading while the regular window is blurred. Account changes, device visibility loss, offline events, graphics failure, navigation and explicit exit retire headset access. Retirement discards previews, aborts pending work, blanks and releases the texture, cancels frame callbacks and detaches account and device listeners. Recovery requires new actions.
