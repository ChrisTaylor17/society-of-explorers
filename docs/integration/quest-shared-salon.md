# Shared salon check-in

Open an online or hybrid Circle’s Quest Browser view. Connect the existing email or Google account, then choose **Check member session** and **Join shared salon in this browser**. On a compatible headset, **Enter shared salon in headset** opens a separate panel. The first controller trigger checks the selected account. The second checks current membership and joins the count. Point at **Leave salon** and press the trigger to leave the count, or squeeze to exit the headset room. Leave your browser seat before switching to the headset.

The same count appears in the regular browser and headset. It includes your own seat. Choose **Read Circle discussion** to read or write short posts and replies in the same headset session, or **Read selection** to open the current assignment from a supported edition. Both check current Circle membership. Your seat renews while you read or write. Choose **Back to salon** to see the count again. If a renewal fails, the headset clears the panel and closes the room. [Headset reading](quest-immersive-discussion.md#reading-in-the-room)

While checked in, open the latest discussion archive in Quest Browser or choose **Read Circle discussion** in the headset. After a successful check-in, the latest page checks for changes about every ten seconds. Older pages, open threads, drafts and message actions stay in place. In the browser, updates also pause while an archive control has focus. In the headset, the first preview follows new posts and the older previews stay where you left them. A membership refusal clears the open archive.

In the headset salon, point at **Meeting in browser** to release your seat and return to the Circle’s Quest page. Check your member session there and choose **Open live meeting**. The live-meeting control is also available in Quest Browser when the shared count is disabled.

## Live meeting handoff

The browser checks current membership through the same Circle details endpoint used by the regular app. It opens the host’s HTTPS link in the same tab for members of an open online or hybrid Circle. Focus loss, a changed account or leaving the page retires a pending request. The app sends the link to the browser for navigation without app credentials or the Circle page as referrer. Back returns to the Quest page and requires a fresh account connection. The host’s meeting runs in Quest Browser after the immersive room closes. Its behavior on a physical headset remains open. [Handoff verification](quest-meeting-handoff-verification.json)

The regular web Circle now uses the same fresh check and same-tab handoff. Choose **Open the online meeting** after loading Circle access. The action confirms the same member account and checks the Circle before opening the host’s link. Going Back requires another access check. The native directory uses its existing fresh read and opens the meeting through the phone.

The Circle API supplies the live URL for current members of open online or hybrid Circles. Completed and expired Circles still support eligible discussion and leaving. The updated shared parser clears an old URL in a valid ended Circle response. Pair the API with updated clients during rollout so completed-Circle detail remains available. The host’s meeting service controls links after they have been shared. [Web and cross-platform verification](circle-meeting-verification.json)

## Account and seat lifetime

Quest Browser sends the selected sign-in attempt with private discussion, check-in, reading access and meeting access requests. The current browser cookies must confirm that choice on arrival at the app. Public passage requests remain anonymous. [Browser account verification](quest-browser-account-verification.json)

Salon requests begin after the member chooses to join. The server accepts same-origin requests, resolves the current account from its credential and checks the Circle and membership again in PostgreSQL. It also accepts the browser’s same-origin request metadata and an origin matching the request host when the server runs behind a proxy. Only the seat state and aggregate count return to the browser. The service keeps one current lease per Circle member. The initial reservation is invisible, then a confirmed check-in makes it visible. The browser refreshes every 10 seconds while active. A visible seat expires 35 seconds after its last successful update. A confirmed leave removes it immediately. Closing the view, changing accounts or losing headset focus clears local state and stops updates. An in-flight server operation can still finish. [Fetch Metadata specification](https://www.w3.org/TR/fetch-metadata/#sec-fetch-site-header)

Membership removal deletes the corresponding lease. Hidden and completed Circles refuse check-ins. The seat store has row-level security and no direct grants for browser roles. The RPC uses the service role. It checks the Circle before the member’s seat and serializes updates for that membership. An expired row drops out of the count immediately and can be pruned by later check-ins to the same Circle. Idle Circles can retain an expired row per member until cleanup, membership removal or rollback. [Supabase API access controls](https://supabase.com/docs/guides/api/securing-your-api) · [PostgreSQL row locks](https://www.postgresql.org/docs/current/explicit-locking.html) · [WebXR visibility state](https://immersive-web.github.io/webxr/#xrsession-visibility-state)

## Pilot switch and proof

`SOE_SHARED_SALON_ENABLED=true` exposes the controls and enables the endpoint. The default app omits the controls and returns a private 503 for check-in requests. The SQL apply and rollback are review drafts. Before enabling a hosted pilot, rehearse them on the approved isolated restore and set a cleanup cadence for idle Circles. Disable the switch before rollback. [Apply SQL](../sql/circle-salon-presence-apply.sql) · [Rollback SQL](../sql/circle-salon-presence-rollback.sql)

Nineteen composed Chromium scenarios covered the shared salon. The latest discussion showed each member’s saved post on the other member’s next check-in. Drafts survived check-ins and membership removal cleared private discussion. The run used simulated headset input, actual WebGL, Circle handlers and disposable PostgreSQL. The standalone discussion run passed 20 scenarios. Physical Quest and hosted account checks remain open. [Live discussion verification](quest-live-discussion-verification.json) · [PostgreSQL contention verification](quest-shared-salon-verification.json)

To reproduce with the existing cached runtime, pass the same fresh suffix, such as `immersive-salon-05`, to the composition bundle and `platforms/tests/browser-quest-salon-presence.mjs`. Run the browser command from the repository root with the root-relative startup guard. Run `python3 -B verification/web/scripts/test-salon-presence-locks.py --receipt verification/web/evidence/salon-presence-locks-02.json` for the independent PostgreSQL checks. Choose a new evidence suffix for each run. [Cached-runtime commands](quest-member-composition.md#reproduce-without-downloads)
