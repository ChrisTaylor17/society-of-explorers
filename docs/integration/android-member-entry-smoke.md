# Android member entry smoke test

The previous device test waited for a reciprocal-contact demo that the registered app no longer renders. The replacement targets the separate embedded synthetic APK with the exact fixture identity and blank account policy. It launches the real MainActivity and checks that the member entry loaded its packaged JavaScript. It presses the app's Connect button, checks the installed member module is registered, then verifies the unavailable message and absence of credential inputs or member entry. Background and foreground leave that state closed. Recreating the activity returns to the initial Connect screen. The test uses the app's own native view tree, with no real account, fixture server or device settings change. The old demo test remains in Git at `ae2143a`.

The refreshed [browser proof](android-member-entry-verification.json) passed 15 stories using the registered App, real AuthClient library, current account and message handlers, and disposable SQL. The first story exercises the actual default connection factory with an absent native module. Configured stories use synthetic provider and native/OS ports; the fixture now applies the current publication filtered message state wrapper rather than returning HTTP 503 because it is missing. The author selects a contribution, gets current state and confirms withdrawal before the actual local SQL action. The two failed fixture runs remain available for diagnosis.

A separate activity test captures a foreground request epoch and moves the real activity to the background. It checks that pause reports a retirement cutoff and refuses a fresh epoch while inactive. After resume it checks that a new epoch is available and the earlier one is refused. It remains pending on an installed synthetic APK. [Foreground verification](android-foreground-epoch-verification.json)

The synthetic Android test suite has three storage tests for the real Android vault and Keystore. They use an isolated namespace, check an empty vault after a successful clear and reopen, block an encrypted file replacement during a reset, and check that an ordinary write failure closes the cached vault. The interrupted-reset case restores the old ciphertext alongside the committed marker to check that a fresh vault finishes the clear. Run these tests on an unlocked device or emulator using the synthetic build. Android compilation and these device tests remain open. [Storage verification](android-vault-commit-verification.json)

The 21 Android policy checks verify source or executable local policy helpers. The checked manifest has no additional main permissions; backup exclusions and release signing guards remain covered. This is not a merged Android manifest check.
