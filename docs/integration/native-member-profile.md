# Native member profile

This milestone extends checkpoint `a381d1710425d4cc974716700e95b7eb83ed0550` in `/Users/christaylor/Documents/Codex/soe-release`, branch `codex/soe-first-release`. Production clearance remains false. The [verification receipt](native-member-profile-verification.json) records the current source, test groups and local evidence.

After owned sign-in and a canonical member check, **My profile** opens an inert screen. **Load my profile** explicitly fetches the current owner, revision, visibility and seven authored fields. Editing includes display name, biography, field, skills, project, what the member seeks and philosophy. Visibility is a separate choice. **Review profile changes** shows the normalized complete profile, followed by an explicit save or save-and-publish confirmation. Cancel returns to the draft without sending it.

Every private request obtains fresh credentials for the current verified account. The existing server checks the canonical member identity and expected revision; its SQL locks the member row and applies a compare-and-set update. Concurrent changes produce a conflict instead of overwriting another writer. A changed write must return the next revision. An apparent no-op may retain its revision or advance it when legacy null fields are normalized. The UI requires both a matching success receipt and a separate matching fresh owner read before reporting a successful save. This milestone changes neither that route nor its SQL.

An uncertain write stays uncertain. A fresh read at the original revision cannot establish that an earlier request will never arrive. The controller retains the exact reviewed patch, original revision and bound author privately in memory. A newer canonical revision prevents the older compare-and-set from changing current state; it does not prove which writer committed. Otherwise **Review retry of same profile save** presents the original values again, and a new explicit confirmation sends the identical body and revision. A refused retry cannot settle the earlier attempt. No reconnect, timer or transport failure automatically resends a write.

Ordinary Back, background, blur and offline/unknown connectivity clear visible profile fields, drafts and public results. Recovery information for an uncertain save remains in the same open owned-account connection. Ordinary Back preserves the verified member context; reopening requires an explicit profile load with fresh credential proof before the pending review can be shown. Background, blur and connectivity retirement additionally require explicit provider restoration and canonical member checks. A different canonical member destroys the earlier profile connection. Closing the member view, closing sign-in, clearing device sign-in or replacing the owned connection discards local recovery; an already-sent server request may still finish. This is in-memory recovery only, not durable recovery across app termination. Navigation is disabled while a request is busy; ordinary Back is available after an uncertain request has stopped waiting.

The screen and account menu also retire callbacks when their view, authority or selected child changes. Profile review transitions retire older Confirm/Cancel callbacks, including after cancellation and a new review in the same mounted screen. Late responses and retained callbacks cannot restore an old view, submit a newer review or close a replacement member context.

**Check my public profile** is a separate explicit anonymous request. It displays only the server's strict authored-field projection for the current member. No bearer, API key, cookie, Circle identity or provider check is sent on this path. A canonical generic 404 means the public profile is unavailable on that check. An unavailable or malformed response makes no publication claim. Unpublishing requires another reviewed owner save and fresh private readback; a public self-check does not prove removal from third-party caches.

The [transport contract](native-profile-transport.md) adds optional independent private and public capabilities. Older native modules fail closed: absent private capability disables profile entry; absent public capability disables the public self-check while private editing remains available. Existing member, Circle discovery, passage and provider routes retain their separate allowlists. The public DTO parser is an additive shared export; existing web behavior remains unchanged.
