## Reproduced defect and narrow fix

The previous player owned requests and blob URLs for its component lifetime, while the page key contained only clip ID and media SHA. A caption-only review revision therefore retained an old ready caption URL; an old pending caption read could also finish under the new review. Both cases reproduced in actual React 19.2.4 and Chromium with the real first-party MP4 and an isolated caption revision fixture. Baseline evidence: `verification/web/evidence/clips-independent-review-baseline.json` (both mismatch flags true; baseline player SHA `3cbfc9b69651c65ae2c8d880cda1df98749a8cad1f168ec614b9ed3e38fbb9d9`).

`app/clips/ClipPlayer.tsx` now parses the bounded public DTO in an outer component and keys the internal player by the entire canonical parsed DTO. Any caption, media, timing, title, credit, or review change retires the previous request/blob owner even when an external caller keeps its parent key. Existing abort, generation fence, unload, and URL revocation behavior remains in the internal player. No other product source changed during this review.
