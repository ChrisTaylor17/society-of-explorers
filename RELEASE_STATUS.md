## Current message-safety milestone

Native and Quest now check the selected contribution through the canonical message-state API before showing report/withdraw permissions. Opening actions clears the old archive, message bodies and reply preview. Reports need a reason, optional bounded private note and explicit confirmation; authors see the withdrawal/retained-evidence disclosure before confirming. Reports are allegations for private human review and do not enable AI processing or change consent.

An uncertain POST retains one exact request in memory for manual retry. **A current-state GET never proves a report receipt.** Only a matching receipt from the original POST or its exact replay confirms the action. Pending requests block other writing/navigation. Account, activity, connectivity, access or closure changes clear private local state and keys; late replies cannot restore them. Already dispatched actions may still commit. Nothing retries automatically.

Authors can withdraw an already-loaded contribution after leaving a Circle or after moderation hides it, subject to fresh server authority. This does not add a cross-Circle own-contributions list for a new session. Withdrawal removes member-visible content; restricted evidence remains and retention policy is unfinished. See [native scope](docs/integration/native-message-safety.md) and [Quest scope](docs/integration/quest-message-safety.md).

The shared host uses bounded secure UUID acquisition. Quest uses `crypto.randomUUID`; Android's optional, generation-fenced OS UUID capability has no weak fallback. Transport permits only exact message GET/POST paths with UUIDs and no query/suffix. Server routes and SQL were unchanged in this milestone. Android Kotlin changes are source only.
